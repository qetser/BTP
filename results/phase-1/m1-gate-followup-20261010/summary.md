# M1 gate follow-up: independent validation alternatives

**Status:** P1 is blocked at binary retrieval after exhausting the identified official routes. ODE returned the exact candidate label and file inventory. The JPL binary host fails strict TLS validation here; the documented USGS PDS4 mirror path now returns 404, and NASA Open Data lists no downloadable resources. Actual valid-pixel overlap and all M1 calibration/mask gates remain open.

**Source data:** Existing matched IIRS E1G2 observation `20260227T1239538758`; published IIRS–M³ spectral comparison (LPSC 2021 abstract 2436); IIRS Level-2 reflectance method (LPSC 2025 abstract 1876); IIRS recalibration/thermal workflow (LPSC 2025 abstract 1644); PDS M³ archive index.

**Method:** Exa searches and source fetches were used to review primary conference abstracts and official PDS archive documentation. Queried the NASA PDS Geosciences Node ODE REST endpoint for candidate `M3G20090206T010833_V01_RFL` with `results=fl`, which returned the full PDS3 label text and linked file inventory. Reproduced the product-specific metadata query with `results=m`. Saved concise label metadata and file links in [`m3_candidate_ode_metadata.json`](m3_candidate_ode_metadata.json). The earlier literature-review pass recorded 147 search-result slots; the additional P1 endpoint searches are not included in that count. Search results can overlap and the count is not unique sources.

**Observations:** ODE returned the full label for `M3G20090206T010833_V01_RFL`: a global-mode product with 304 samples × 27,796 lines × 85 `PC_REAL` bands, invalid constant -999, and thermal-correction flag `Y`. The label references source pixel-location product `M3G20090206T010833_V03_LOC.IMG`. ODE lists the RFL cube as 2,700,001 KiB and links the label, cube, supplemental data, and headers to the official JPL Imaging Node. Strict TLS requests fail with a self-signed certificate-chain error. Exa identified the USGS-hosted PDS4 bundle route documented by the conversion repository (`https://pdsimage2.wr.usgs.gov/Chandrayaan_1/`), but requests to its root and likely volume paths return 404. NASA Open Data marks the dataset as having no data resources. No binary image or location cube was downloaded and no valid-pixel overlap was computed. Three published validation routes remain supported: normalized IIRS–M³ spectral shape only; Apollo 16/RELAB 62231 absolute reflectance on a separate scene; and Diviner temperature comparison matched by ground control points and acquisition time. These do not resolve local Level-1 units or pixel masks.

**Limitations:** ODE provides metadata, label text, and file links but points to the JPL Imaging Node. The local TLS validation failure prevented downloading the 2.7 GB RFL cube and its source LOC cube. The documented USGS PDS4 mirror URL is presently unavailable at the probed paths. No TLS verification was disabled. The current scene has no local independent absolute radiance standard. M³ Level-2 reflectance is not an independent IIRS radiance truth product. Common valid-pixel overlap remains unmeasured, and the local strip does not cover Apollo 16. Diviner comparison checks derived temperature under matched conditions, not absolute IIRS radiance calibration. No new numeric result was computed.

**Next gate:** Resume retrieval when an official PDS host serves the documented USGS mirror or the JPL TLS chain validates in this environment, or when the user provides the official RFL/LOC files locally. Then map M³ pixel locations and -999 validity against IIRS geolocation to compute actual common valid-pixel coverage. Use any eventual spectral comparison as a shape check only. Continue local label/SIS/guide evidence review for the unresolved unit, fill, and pixel-validity semantics. Keep thermal/3 µm science gated until the E1G2 mask, units, geometry, and thermal residual checks pass.
