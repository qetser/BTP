# E1G2 saturation-field sample probe

**Status:** Two exploratory diagnostics completed. The fixed-line E1G2 sample reproduces the full-cube mismatch. A table-only check across E1G2 and E3G2 finds very different LUT-to-saturation ratios by mode. E1G2 is closer if its saturation number is treated counterfactually as mW; E3G2 is not. This rules against applying one simple unit correction across modes, but does not establish the correct interpretation for either mode. No pixel mask was assigned and the M1 gate remains open.

**Source data:** Paired 2026-02-27 E1G2 Level-0 raw-count and Level-1 calibrated-radiance products, plus the official IIRS E1G2 saturation table and gain/offset LUT. Source pair paths and observation identity are recorded in [the E1G2 acquisition summary](../m1-e1g2-scene/summary.md).

**Method:** Reproducible command: `uv run --no-project --with numpy --with matplotlib python scripts/probe_iirs_saturation_sample.py`. The script streamed paired BSQ cubes from their ZIP archives and retained 16 scan lines spread from the first through last line, all 250 spatial samples, and all 222 E1G2-valid bands. The 0-based line indices are in the JSON output. It counted radiance values at or above the table's `Saturation` field and raw counts at or above `Dynamic_Range`, then compared sampled calibrated values in mW with raw-count predictions from the official LUT. This is a deterministic spatial sample, not a random sample or train/test split.

**Data version and code:** Observation `20260227T1239538758`; calibrated units and saturation XML units are both `µW/cm**2/sr/µm`. Git base revision: `304c5e8bc880d754ecab0b75983c8370b73d033e`; the probe script is uncommitted and has SHA-256 `2383e65bf6ceab59b52148c4ab135a43109f1a2fb7109a9d3a8f4c87d93a9a58`.

**Table-to-LUT check:** For every mode-valid band and all 250 LUT sample positions, applied the LUT gain and offset to that band's `Dynamic_Range` count. The E1G2 counterfactual mW median LUT/saturation ratio is **1.559** (10th–90th percentile 1.028–1.856). The E3G2 ratio is **5,118** (10th–90th percentile 1,029–8,993). Both saturation XML files declare µW, so interpreting E1G2 as mW does not provide a consistent cross-mode correction. See the [per-band CSV](metrics/iirs_saturation_lut_table_check_by_mode.csv), [JSON](metrics/iirs_saturation_lut_table_check_summary.json), and [figure](figures/iirs_saturation_lut_table_check.png). Reproduce with `uv run --no-project --with numpy --with matplotlib python scripts/check_iirs_saturation_table_vs_lut.py`; script SHA-256 `2c62ef8d24371bc657ce092d8aeb9f5c56b7cca0574101a087efb3e3386527b7`.

**Observations:** Across 888,000 valid-band sample observations, 868,507 (97.8048%) calibrated values meet or exceed the saturation threshold as labeled. No raw count meets the table's dynamic-range value. The median across valid bands of each band's sampled calibrated/LUT median ratio is 1.00139. Sampled raw counts range from 0 to 8,439. Per-band saturation candidate fractions range from 96.35% to 99.70%; per-band median LUT ratios range from 0.9060 to 1.0960. See the [machine-readable counts](metrics/e1g2_saturation_sample_by_band.csv), [summary JSON](metrics/e1g2_saturation_sample_summary.json), and [figure](figures/e1g2_saturation_sample_flags.png).

**Limitations:** This sample was selected by fixed line positions and is not statistically independent. The per-band LUT ratio spread shows that the aggregate median alone hides band-level variation. LUT agreement is an internal consistency check, not independent calibration validation. Threshold exceedances are diagnostic candidates, not confirmed saturation labels. This probe cannot determine fill values, define a valid-pixel rule, or establish that the two table fields should be applied directly to Level-1 pixels.

**Next gate:** Compare actual raw-count distributions and LUT-predicted radiance with calibrated values for the available E3G2 raw/calibrated pairs, keeping `m65` and `d18` product units distinct. This can further localize the discrepancy without waiting for a reply, but cannot establish an official Level-1 mask rule. Keep pixel-mask and M2 gates open until fill/validity behavior has a defensible basis.
