# M1 reference-data notes

- Review date: 2026-09-29.
- The LROC WAC global morphologic map page reports a 100 m/pixel product. The PYR TIFF is 1,617,959,634 bytes and supports byte ranges. On 2026-09-29, `scripts/fetch_wac_reference_crop.py` fetched 164 256 x 256 tiles (10,747,904 bytes) and assembled an 824 x 10,230 pixel PGM crop with 20 km margin around the projected IIRS control grid. The ignored raster is `data/reference/lroc_wac_e1g2/e1g2_wac_crop.pgm`; its source version, GeoTIFF scale/tiepoint, crop origin, projection assumption, and retrieval details are in `wac_crop_metadata.json`. A preview was visually inspected. This acquisition is not registration evidence.
- The PDS M³ Level-2 profile states the archive contains pixel-located, reflectance-calibrated observations from the Chandrayaan-1 mission. Five intersecting label IDs were returned; no image product has yet been selected or downloaded.
- Queried ODE REST on 2026-09-29 with target `moon`, instrument host `CH1-ORB`, instrument `M3`, product type `REFIMG`, `loc=f`, west/east longitudes 354.5/356.5°E, and min/max latitudes -7/27°. It returned five product footprints. The CSV retains the returned observation, orbit, center, label URL, and label product ID. `loc=f` requests footprint intersection; product labels and valid-pixel masks remain to be inspected before acquisition.
- An otherwise identical ODE count query using `loc=b` (bounding-box intersection) returned 145 candidates. The footprint intersection returned five. Use the latter shortlist, then inspect actual labels and valid pixels before treating any pair as usable overlap.
- On 2026-09-29, retrieved each of the five public PDS3 labels through Firecrawl scrape. The labels describe 304 x N x 85 Level-2 reflectance products, thermal correction flag `Y`, and special pixel -999.0. `m3_label_review.csv` records the label-derived fields and source URLs. The cube images and per-pixel location arrays were not downloaded.
- Used ODE's returned longitude/latitude footprint geometries with the 1,476-point IIRS geometry table. The point-in-polygon screen uses even-odd ring parity, counts boundary points inside, and compares coordinates in positive-east 0–360 longitude. The highest-count candidate is `M3G20090206T010833_V01_L2` at 1,033 points. This does not account for between-control-point geometry, M³ validity masks, or per-pixel image areas.
- The 2026 E1G2 cube dimensions are 250 samples x 12,210 lines. Its geometry table has six sample coordinates at each of 246 scan positions spanning lines 0–12,209. Earlier notes incorrectly described the number of scan positions as a count of image lines; README, summaries, and task records now use the correct axes.
- Reproduce the browse-scale registration with `uv run --python 3.11 --with numpy --with opencv-python-headless --with matplotlib python scripts/register_iirs_to_wac.py`. The analysis interpolates the sparse geolocation grid, projects to the WAC orthographic map, remaps WAC to the IIRS image, and matches local x/y gradient patches. Spatial blocks and guard bands separate training ties from held-out ties.
- The browse-scale comparison produced 23 accepted training tie windows and 8 accepted held-out windows in two along-track blocks. Held-out residual RMSE is 0.781 IIRS cube-pixel equivalents (57.4 WAC projected map metres); 95th percentile is 1.075 pixels (78.0 projected map metres). Values and figure are `metrics/iirs_wac_registration_browse_ties.csv`, `metrics/iirs_wac_registration_browse_summary.json`, and `figures/iirs_wac_registration_browse_residuals.svg`.
- Extracted official calibrated E1G2 band 40 (1,369.6 nm), marked valid in the E1G2 workbook, and stretched its finite values between the 1st and 99th percentiles for image matching. `scripts/extract_iirs_registration_band.py` recreates the ignored 250 x 12,210 PNG and its metadata JSON under `data/reference/lroc_wac_e1g2/`. The raster is used only for surface morphology, not radiance interpretation.
- Reproduced registration on full-resolution band 40 with `uv run --python 3.11 --with numpy --with opencv-python-headless --with matplotlib python scripts/register_iirs_to_wac.py --iirs-image data/reference/lroc_wac_e1g2/e1g2_band040_1369nm.png --iirs-image-metadata data/reference/lroc_wac_e1g2/e1g2_band040_1369nm.json --image-description 'E1G2 calibrated band 40, 1369.6 nm, 1-99 percentile display stretch' --artifact-suffix band040_1369nm --search-radius 16`.
- Full-resolution matching produced 30 accepted training ties and 12 held-out ties in 3 spatial blocks. Held-out residual RMSE is 2.757 IIRS pixels (198.2 WAC projected map metres); 95th percentile is 5.317 pixels (382.7 projected map metres). See `metrics/iirs_wac_registration_band040_1369nm_ties.csv`, `metrics/iirs_wac_registration_band040_1369nm_summary.json`, and `figures/iirs_wac_registration_band040_1369nm_residuals.svg`.
- The larger full-resolution residuals indicate that the browse-scale figure alone was optimistic. Both diagnostics are provisional image-alignment checks, not surveyed absolute controls. Three held-out spatial blocks and twelve image patches are not enough to close full-resolution geolocation validation. Software used was Python 3.11.16, NumPy 2.4.6, OpenCV 5.0.0, and Matplotlib 3.11.2.
- A search result for the IIRS SIFT registration work is a Preprints.org manuscript, not a peer-reviewed journal article. It describes sparse IIRS coordinate tags and LRO WAC registration; treat it as a method lead only.
- No M³ image cube was downloaded. Candidate metadata and label fields are saved as CSV; the sparse-grid screen is saved as CSV and SVG. It is a candidate-ranking diagnostic only, not a validated geometric or spectral metric. Preliminary WAC-to-IIRS tie residuals are now saved, but they do not constitute surveyed absolute geolocation validation.
- Apollo 16 longitude was checked against the E1G2 footprint for planning; the ground-calibration site is outside the footprint. Do not treat that paper's ground comparison as local validation.
